# back-navigation-policy — 뒤로가기 정책

## 🎯 목표

현재 뒤로가기는 스택이 비면 **즉시 앱 종료**된다(트래킹이 루트라 실수 종료·공유 끊김 위험).
아래 우선순위로 동작하게 한다.

## 🧭 확정 정책 (우선순위)

1. **팝업/바텀시트/다이얼로그가 열려 있으면 → 그것을 닫는다.**
2. 화면 이동 스택에 pop할 곳이 있으면 → 이전 화면으로.
3. 둘 다 아니면 → **두 번 눌러 종료** (첫 탭에 "한 번 더 누르면 종료됩니다" 토스트, 2초 내 재탭 시 종료).

## 🛠️ 구현 방식

Compose의 back 처리 우선순위(늦게 등록된 핸들러가 먼저)를 그대로 활용한다.

- 앱 루트(`MeetPinNavHost` 최상단)에 **더블탭 종료 `BackHandler`**를 둔다 → 가장 낮은 우선순위 = 최종 폴백.
- `NavHost`는 pop할 목적지가 있을 때만 자체 콜백을 활성화 → 자동으로 2순위.
- 팝업/시트/다이얼로그는 각자 `BackHandler`(또는 `ModalBottomSheet`/`Dialog` 기본 동작)로
  가장 높은 우선순위를 가져 1순위로 닫힌다.

즉 화면마다 분기 코드를 넣지 않고, 컴포넌트가 열릴 때 자기 back만 등록하면 정책이 성립한다.

## 📝 세부 작업

- [x] `MeetPinNavHost`에 더블탭 종료 `BackHandler` + 토스트 추가
- [x] 향후 추가되는 바텀시트/다이얼로그는 열림 상태에서 자체 back(닫기)을 등록하도록 규약화
- [x] 예측형 뒤로가기(Android 13+)와 충돌 없는지 확인

## 🔍 검증 기준

- 루트(트래킹/생성)에서 뒤로가기 1회 → 토스트, 2초 내 재탭 시에만 종료
- (팝업 도입 후) 팝업 열림 상태에서 뒤로가기 → 앱 종료 대신 팝업만 닫힘
