# Phase 3: 기타 화면 반응형 레이아웃 대응

> **상태: ✅ 완료 (2026-07-30, 축소 범위) — 런타임 확인 대기**
>
> 티켓 작성 이후의 화면 재설계로 원 전제 상당 부분이 소멸하여, 실제 코드에 맞춰 축소 수행.
>
> **수행한 것**
> - `InviteAcceptScreen`: 초대 카드(`InviteCard`)와 에러 컬럼에 `widthIn(max = 480.dp)` 적용.
>   대화면에서 카드가 가로로 흉하게 늘어나던 문제 해소. 폰 폭(<480dp)에선 no-op이라
>   사이즈 클래스 게이팅 불필요(자기조정형). → 티켓의 "폼/카드 최대 너비 제한" 취지 반영.
>
> **전제 붕괴로 미수행 (사유)**
> - **`LobbyScreen` 참가자 그리드**: 해당 화면이 존재하지 않는다. 네비게이션상
>   `InviteAcceptEffect.NavigateToLobby` → `MeetPinRoute.liveTracking`으로 라우팅되어
>   "대기실 = 실시간 트래킹 화면"이다. 그 화면의 태블릿 좌/우 분할은 **phase2에서 완료**.
>   → 없는 화면의 `LazyVerticalGrid`를 신설하지 않는다.
> - **`CreatePinScreen` 폼 `widthIn`**: 이 화면은 폼이 아니라 **전체화면 지도 + 중앙 핀**
>   (즉시 공유 플로우)로 재설계됨. 태블릿에서 전체화면 지도가 정상이고 "약속 만들기"
>   말풍선은 `align(Center)`라 이미 스케일된다. → 변경 불필요.
>
> **검증**: `:feature:lobby:compileDebugKotlin` 성공. 태블릿 시각 확인은 미수행(런타임).

## 🎯 목표
- 약속 생성 화면 및 대기실(Lobby) 화면도 태블릿 환경에 맞게 최적화합니다.

## 🛠️ 수정 대상
- `CreatePinScreen.kt`
- `LobbyScreen.kt`

## 📝 구체적인 구현 방향
- 폼(Form) 요소가 많은 화면은 `Expanded` 상태에서 양옆 여백을 주어 입력 필드가 너무 길어지지 않게 최대 너비(`widthIn`)를 제한합니다.
- 대기실의 경우 참가자 리스트를 그리드(`LazyVerticalGrid`) 형태로 보여주어 가로 공간을 넓게 활용합니다.
